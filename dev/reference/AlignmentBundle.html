AlignmentBundle

alignment.AlignmentBundle(
    id='',
    name=None,
    timelines=dict(),
    groups=dict(),
    meta=dict(),
    support_policy=SupportPolicy.omit,
    styling=dict(),
    resources=list(),
    _warp_map_cache=dict(),
    _matchline_cache=dict(),
    _matchgraph_cache=dict(),
    _in_force_cache=dict(),
    _naming_cache=dict(),
    *,
    seed=None,
)

The primary entry point for all alignment workflows.

An AlignmentBundle manages timelines and their alignment relationships. Within a group, coordinate transfer uses linear interpolation (TimelineGroup.get_coordinate_at()). Across groups, transfer is mediated by the MatchClaim → MatchLine → WarpMap pipeline.

The bundle provides:

  • Timeline registration and lookup
  • Group management (collections of perfectly aligned timelines)
  • Coordinate transfer between any two timelines (same-group or cross-group via MatchClaim/WarpMap)

The alignment relationships and coordinates do not depend on the order in which timelines are added; the order of table rows and columns and of a stamp’s coordinates follows registration.

Attributes

Name Type Description
id str Unique identifier for this bundle, minted with the prefix bundle unless given.
name str | None Optional human-readable name.
timelines dict[str, 'Timeline'] Dictionary mapping timeline IDs to Timeline objects: every timeline added, and the root of every one that is a child. The other descendants of these roots are not listed, yet every getter answers for them as for the listed ones.
groups dict[str, TimelineGroup] Dictionary mapping group IDs to TimelineGroup objects. The groups are the one statement of membership; a timeline may be a member of several (see :attr:timeline_to_groups).
match_claim_table MatchClaimField The bundle’s MatchClaims, every kind, in one :class:~timetoalign.alignment.claims.MatchClaimField (the MatchClaim table), queried vectorized; a claim is materialised only where a reader needs the object. A MatchClaim is addressed by its id alone.
styling dict[str, Any] The members of the manifest’s graphical other than order (styles, rules, timestamps and any other), kept as given and never interpreted.
statements dict[str, list[Any]] What the manifest stands for, as property–value pairs, with their :attr:provenance (see :mod:~timetoalign.timelines.statements).
resources list[Resource] The files the manifest names (its resources), each a :class:~timetoalign.timelines.manifest.Resource: the MatchClaim table and the Projections table that :meth:to_file writes beside the manifest, and any other kept as read.

Note

Every reader of the MatchClaims (queries, the matchstamp getters, the table getter :meth:get_matchstamp_table, the MatchLines and WarpMaps behind transfer) reads the one table, through the belief filter (believer, beliefs) where the reader takes it. Two bundles are equal when their claims are too: the tables are compared row by row, provenance included (:class:MatchClaimField equality).

Examples

>>> from timetoalign.alignment import AlignmentBundle
>>> from timetoalign.timelines.types import (
...     ContinuousLogicalTimeline,
...     ContinuousPhysicalTimeline,
... )
>>> bundle = AlignmentBundle()
>>> _ = bundle.add_timeline(ContinuousLogicalTimeline(length=200, uid="score"))
>>> _ = bundle.add_timeline(
...     ContinuousPhysicalTimeline(length=91.0, uid="audio"), grouped_with="score"
... )
>>> stamp = bundle.get_matchstamp_at(100, "score")
>>> stamp.get_coordinate_for("audio", format="float")
45.5

Record actor’s belief in the pair (property, value).

The pair’s entry, made where the pair has none, records the belief, replacing the actor’s earlier one (:func:timetoshare.with_belief). Whether the pair is stated is left as it is: believing a stated pair "false" records the belief and never removes the pair, and every other actor’s belief stands. A candidate the actor believes "false" is left out of :meth:get_candidates for that actor.

add_group

alignment.AlignmentBundle.add_group(group)

Add a pre-built TimelineGroup with all its timelines at once.

This is the bulk-registration counterpart of add_timeline(..., as_group=...). It registers the group and every timeline it contains — each under its own id, with the root of every member that is a child — into the bundle’s timeline and group registries. A member may already be a member of another group of the bundle: a timeline may belong to several groups. The group keeps its id.

add_match_claim_belief

alignment.AlignmentBundle.add_match_claim_belief(
    claim_id,
    *,
    actor,
    belief,
    date=None,
    note=None,

Record actor’s belief in the MatchClaim claim_id.

A MatchClaim is never removed and never changed: invalidating one is believing it "false", and a correction is a new MatchClaim. Only the claim’s provenance changes. The belief replaces the actor’s earlier one in that claim, actors compared as IRIs under the bundle’s @context, every prefix it declares (a compact and an absolute spelling of one actor are one actor); every other actor’s belief stands. A claim stated without provenance gets an entry holding the belief alone. The belief filter (believer=, beliefs= on every query) reads it at once; the MatchClaim table written by :meth:to_file succeeds the one written before. A belief in a pair of the bundle’s own statements is recorded by :meth:add_belief.

note str | None A remark. None

Returns

add_match_claims

alignment.AlignmentBundle.add_match_claims(claims)

Add MatchClaims to the bundle’s MatchClaim table.

A claim names timelines of the bundle’s trees, and each of its coordinates is on its timeline’s own axis, its unit and declared number type (:meth:MatchClaim.check_on_timelines): a position in another unit is converted when the claim is made (:meth:create_match_claims, :meth:MatchClaim.from_events), never here, and a claim holding one is refused.

A MatchClaim is addressed by its id alone, and a claim’s id never changes: an id the bundle holds, or one held by two of the claims, is refused, whether it was given or minted. Every claim holds its id from its construction, and joining mints none. Each claim records the bundle (:attr:MatchClaim.bundle); a claim another bundle holds joins as a copy. The table holds the claims’ rows, so a claim read back from the bundle equals the one added but is another object. Every check precedes any change.

WarpMaps are built lazily on first transfer or get_matchstamp_at() call, so adding claims is cheap.

claims Iterable[MatchClaim] The MatchClaims. required

Returns

Name Type Description
'AlignmentBundle' self (for method chaining)

Raises

Name Type Description
TypeError If an item is not a MatchClaim.
KeyError If a claim names a timeline the bundle does not hold.
ValueError If a claim’s id is held by another claim of the bundle or by two of the claims, or a coordinate is not on its timeline’s axis.

add_timeline

alignment.AlignmentBundle.add_timeline(
    timeline,
    *,
    grouped_with=None,
    as_group=None,
    seed=None,
)

Add a timeline, optionally grouped with an existing timeline.

This is the primary method for adding timelines to the bundle. Timelines can be standalone or grouped with existing timelines. Group membership makes timelines commensurable through interpolation; it does not by itself assert any MatchClaim between them. A member spans its whole group (see :class:~timetoalign.timelines.TimelineGroup); to let only part of a timeline participate, add the child covering that part.

A timeline is registered under its own id. An ungrouped participant is always a root: a child added without grouped_with or as_group registers its ROOT, and the child stays reachable as the root’s descendant (exactly what the dictionary form restores). A child added to a group joins it, and its root joins the bundle as well, ungrouped unless it is grouped itself.

A timeline may be a member of several groups: one already in the bundle, grouped or not, joins a further group through grouped_with or as_group.

Parameters

Name Type Description Default
timeline 'Timeline' The Timeline to add. required
grouped_with str | None ID of a timeline of the bundle’s trees to share a group with, registered or nested in one; it is registered as a member. If provided, both timelines become part of the same group. If the target timeline is not yet in a group, a new group is created with the target as its first member. A target in several groups is refused, since the group to join would be a guess. None
as_group str | None Name of the group if a new one is created. The new group’s id is minted (:class:TimelineGroup). None
seed int | None The seed of the minter of a new group’s id; not stored. None

Returns

Name Type Description
'AlignmentBundle' self (for method chaining)

Raises

Name Type Description
ValueError If the timeline is already in the bundle while no group is requested, or already in the group it would join; if grouped_with names a timeline of several groups; if an id of its manifest tree — of any timeline, conversion map, region or flow-control element of it — is held by another element of the bundle’s trees, by a group or by the bundle.
KeyError If grouped_with names no timeline of the bundle’s trees, naming every timeline the bundle knows.

Examples

Linear (full-extent) alignment:

>>> from timetoalign.alignment import AlignmentBundle
>>> from timetoalign.timelines.types import (
...     ContinuousPhysicalTimeline,
...     DiscreteGraphicalTimeline,
...     DiscreteLogicalTimeline,
... )
>>> bundle = AlignmentBundle()
>>> _ = bundle.add_timeline(DiscreteGraphicalTimeline(length=4000, uid="scan"))
>>> _ = bundle.add_timeline(
...     DiscreteLogicalTimeline(length=960, uid="midi"), grouped_with="scan"
... )
>>> bundle.get_group_for_timeline("scan").timeline_ids
['scan', 'midi']

Partial alignment: the participating part is a child.

>>> image = DiscreteGraphicalTimeline(length=300000, uid="image")
>>> holes = DiscreteGraphicalTimeline(length=277776, uid="holes")
>>> image.add_child(holes, offset=15343)
>>> audio = ContinuousPhysicalTimeline(length=600.0, uid="audio")
>>> bundle = AlignmentBundle()

create_match_claims

alignment.AlignmentBundle.create_match_claims(
    event_pairs,
    *,
    synchronous=True,
    certainty=1.0,
    provenance=None,
    actor=None,
    date=None,
)

Create MatchClaims between events, projecting a side that has none.

A MatchClaim connects two sides. Each tuple (event_a, timeline_a_id, event_b, timeline_b_id) names one side per timeline, each side one of:

  • the id of an event its timeline (or a descendant of it) holds: the timeline’s own event answers for its ID; an ID the timeline does not hold and two of its descendants do names no one event and is refused (name the descendant holding the event instead);
  • an event dict whose id its timeline holds: that event;
  • an event dict stating a position: start, and end for a span, each a number on the timeline’s axis or a :class:~timetoalign.core.Coordinate in any unit one of the timeline’s C-Maps converts, and optionally name. On a timeline counting samples a position is an int or a Coordinate, never a bare float. A span runs forward (end at or after start). A Projection stands for the side there, on the timeline’s axis (:meth:Timeline.add_projections): under the dict’s id (an event the bundle does not hold, projection_of null), or, without one, naming the other side’s event in projection_of when the other side is an event its timeline holds (null when the other side is NOMATCH or both sides are positions of a conceptual pair). The timeline keeps one Projection per event and position: a second call with the same pairs reuses every Projection the first added. An id the timeline already holds names that event; given with start/end, they must be the event’s own span. The name is the claim’s name of the Projection: the name the first claim on a Projection recorded is the one every later claim on it shows. Where both sides of a synchronous pair are dicts without id, no Projection stands for either: both sides are :data:~timetoalign.core.ids.CHUNK, the claim’s anchor holding the two positions (an interval where both state an end; a name names the stated position and is kept as that side’s event_X_name);
  • :data:~timetoalign.core.ids.NOMATCH, the NOMATCH sentinel, on one side at most.

The MatchClaim is then made between the two sides, on the two timelines’ own axes (:meth:MatchClaim.from_events); an end on both sides makes an interval claim. A pair with NOMATCH makes a NOMATCH claim for the other side’s event (:meth:MatchClaim.nomatch), its id minted at its construction. The claims join the bundle (:meth:add_match_claims).

Every pair is checked before any Projection is added, so a refusal leaves the bundle and its timelines unchanged: the timelines are the bundle’s, an id names an event of its timeline, at most one side is NOMATCH, every position is placed on its timeline’s axis. A position, a Projection’s or a CHUNK side’s, never lengthens a locked timeline (a loader locks a timeline whose source states its length, such as a recording’s): a position past its end is refused. An unlocked timeline grows to hold it where its parent contains the new end (a parent never grows with its child); a position past an end the parent cannot contain is refused, as is one past where the parent ends a child of unknown length.

from_bundles

alignment.AlignmentBundle.from_bundles(bundles, *, id='', name=None, seed=None)

Merge multiple bundles’ groups, standalone timelines, claims and resources.

Registers every group and standalone timeline from each source bundle into a new bundle, and carries over every MatchClaim unchanged, its id included: a MatchClaim’s id never changes and addresses it alone, so the merged :attr:match_claim_table holds every row once, and two sources holding one id are refused before anything is merged (one of them is to be stated again under other ids first). The statements of the timelines and regions travel with them, and their prefixes; the source bundles’ own statements describe their manifests and are not carried. The sources’ :attr:resources are carried, each under its own ID and as it stands: the merge has one MatchClaim table, one Projections table and one Box table, so the first source’s entry of each table type names the merged table (:meth:to_file writes it there under that entry’s ID) and a later source’s entry of that type is not carried; every other resource, such as an audio file a resource names, is. Each source group is entered as a new group with the same id, members, name and meta, each member keeping its own lock. Groups from different source bundles remain distinct — merging does not itself align timelines across bundles. Add cross-group MatchClaims (e.g. via :meth:create_match_claims) afterwards to align them.

Known limit: the timelines are not copied, the merged bundle shares them with the source bundles.

Query the bundle’s MatchClaims.

All parameters are optional; when none are provided, returns all claims, in table order. Filters are combined with AND logic: a claim must satisfy every criterion set (the unified filter parameters).

The table is filtered vectorized (:meth:get_claim_field) and the rows kept are then materialised, one MatchClaim each, recording this bundle — for a dense pairwise alignment that is O(n) Python objects. Use :meth:get_claim_field when the columnar answer suffices.

Get a cross-group match stamp for a position on a timeline.

Coordinate input is the primary interface for cross-domain coordinate transfer and returns coordinates on every connected timeline. Interval input resolves its endpoints through that same coordinate lane and combines the two results.

A coordinate stamp is the transitive cross-group union reachable from the query. Exact-anchor coordinates from the coordinate’s MatchGraph are overlaid first (exact wins over interpolated), then the assembly walks outward across groups to closure: every reached timeline expands into its own group (by interpolation) and warps into not-yet-reached groups (by WarpMap). is_interpolated is False exactly when the query node itself carries an anchor a claim states.

A timeline whose transferred coordinate falls outside alignment support — the entering coordinate lies outside the transferring WarpMap’s source-anchor hull, or the produced coordinate would fall outside [0, length] — is handled by support_policy. No policy ever yields a negative coordinate or one beyond a timeline’s length.

Get a table of MatchStamps for alignment queries.

Analogous to get_timestamp_table() but for cross-group alignment. Fields are timeline IDs holding their coordinate values; what a row is depends on from_graph:

  • from_graph=False (default) — one row per alignment anchor: an instant claim gives one, an interval claim two (its start anchor, then its end anchor). A row fills exactly two cells and leaves the rest null, so a dense pairwise alignment produces sparse rows.
  • from_graph=True — one row per connected component of the (timeline_id, coordinate) graph the anchors induce, end anchors included. The pairwise rows above collapse into the cross-section they describe: one row per aligned instant, every participating timeline filled.

When claims is None the claims are the bundle’s :attr:match_claim_table, read column by column — no MatchClaim is materialised. Every coordinate is written as the claim holds it, on its timeline’s axis (a claim is checked against its timelines when it is added), so no cell is converted here. The belief filter (believer, beliefs) selects the claims either way.

When at is given instead of claims, each position or event ID is resolved through :meth:get_matchstamp_at and becomes exactly one row — a full transitive cross-section, every reached timeline filled — in input order. from_graph does not apply on this path (the stamps are already collapsed cross-sections) and is ignored.

to_dict

alignment.AlignmentBundle.to_dict(
    minimal=True,
    events=False,
    external_references=False,
)

Write the bundle as a TimeToShare manifest.

The manifest carries the bundle’s id only when one was given (a minted id is never written), its name and meta, every root timeline of the bundle — every registered timeline that is no child, which includes the root of each one that is — as :meth:Timeline.to_dict <timetoalign.timelines.Timeline.to_dict> writes it, sorted by id, and the groups sorted by id, each naming its members by id. graphical.order keeps every group’s member order under its id and, unchanged, the band order read with the manifest of every timeline written, beside the members of :attr:styling. A root no group names is ungrouped. The bundle’s statements and provenance are the manifest’s, and the manifest carries its inline JSON-LD @context with the prefixes its statements use and those its MatchClaim table’s provenance uses (its actors: the table :meth:to_file writes beside the manifest is read under this context), each standing for the namespace the bundle declares (:attr:prefixes), else the catalogue’s; a declared prefix neither uses is not written. The manifest carries its :attr:resources. MatchClaims are not written into the manifest: :meth:to_file writes them into the MatchClaim table beside it. The support policy is a setting of the bundle, not part of the manifest.

minimal bool If False, write every optional key, its default value included (the complete form); by default every key at its default value is left out (the minimal form). True
events bool Write every timeline’s event rows. False

to_file

alignment.AlignmentBundle.to_file(
    path,
    *,
    minimal=None,
    styling=None,
    serialization=None,
    events=None,
    external_references=None,

Write the package: the manifest and, beside it, the bundle’s tables.

As :meth:ManifestFileMixin.to_file <timetoalign.timelines.manifest.ManifestFileMixin.to_file> writes a manifest, with the MatchClaim table and the event tables (:meth:_write_tables), written between a first writing of the manifest, which validates and serializes it before any file is written, and the writing that names them. The tables of Projections and of Boxes are written always; with events (given, or as the file read had event rows or event files), the event table of every other event type the bundle’s timelines hold as well, one file per type beside the manifest (Note.parquet), MatchClaims or none. A manifest never names an event’s ID: the bundle’s events lie in their tables alone, and events writes no event rows into the manifest. A bundle of a package’s manifest (one whose resources name folders) is written into its package with :meth:Package.write_bundle <timetoalign.alignment.Package.write_bundle>.

Raises

Name Type Description
ValueError As :meth:ManifestFileMixin.to_file <timetoalign.timelines.manifest.ManifestFileMixin.to_file> and :meth:_write_tables refuse.
NotImplementedError As :meth:_write_tables refuses a table resource naming a folder, before any file is written.
