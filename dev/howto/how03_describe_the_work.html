How to Describe What a Bundle and Its Timelines Stand For

Statements and provenance on a bundle, a timeline and a region: add_statement, add_verb and rectangles, candidates and beliefs (add_candidate, add_belief, the belief filter), the inline context, and the MEI header and MeLODy imports

How to Describe What a Bundle and Its Timelines Stand For

A TimeToShare manifest holds two planes. Its temporal structure states how coordinates relate: timelines, their nesting, maps, regions and flow control. Its s state what the elements stand for and how those things relate to others, and never nest, order or align anything.

Three kinds of element are subjects of statements: the bundle, which is the manifest itself and names the work it is about; every timeline, at any depth, for the manifestation it is the axis of (an edition, an encoding, a recording file, a video); and every region, for the stretch of that manifestation it marks. A statement is a pair of a property and a value, both identifiers in published vocabularies where they name things; the property type reads “is a”. Works and expressions are never elements: they appear as values, the work under the bundle’s schema:about.

A manifest carrying statements is YAML-LD: its inline @context declares the prefixes its compact IRIs use, so it reads as linked data without fetching anything. The shipped with the TimeToShare package knows the vocabularies, the identifier systems and the verbs that state one relation in each of them.

This guide describes the LayerIt example: an MEI encoding of the first six bars of Debussy’s Clair de lune, a concert video of Maria João Pires and a WAV file cut from its sound. It states what each timeline is, who performs, who said so and who believes it, offers candidates, describes a region, writes the manifest, and imports the description of an MEI header and of a MeLODy repository. The format is specified in TimeToShare’s description of a manifest.

Setup

Install the library with pip install timetoalign; the MeLODy import also needs rdflib, pip install "timetoalign[rdf]". No data is downloaded: the MEI header and the MeLODy repository are written below into a temporary directory. The identifiers are those of public catalogues; the editor who states the pairs and the days are invented.

show prints the pairs of a subject, or of a value node inside it, and the of each pair that has one, marked stated or candidate; a value node’s own entries are shown when show is given that node. show_manifest prints a manifest as canonical YAML, leaving the format’s own terms out of @context so that only the prefixes remain.

import json
import tempfile
from pathlib import Path

from timetoshare import FORMAT_CONTEXT, dumps, to_file_id

import timetoalign as tta
from timetoalign.loader import MeiHeadLoader, MelodyLoader

EDITOR = "https://example.org/people/editor"
REVIEWER = "https://example.org/people/reviewer"
DAY = "2026-11-18"
FOLDER = Path(tempfile.mkdtemp())


def text(value):
    """Write a JSON value on one line."""
    return json.dumps(value, ensure_ascii=False)


def show(holder, node=()):
    """Print the pairs of a holder or of one of its value nodes, then their entries.

    A value node's own entries are left out of its pair; ``node=`` shows them.
    """
    for property, value in holder.get_pairs(node=node):
        if isinstance(value, dict):
            value = {key: item for key, item in value.items() if key != "provenance"}
        print(f"{property}: {text(value)}")
    candidates = holder.get_candidates(node=node)
    for entry in holder.get_provenance(node=node):
        kind = "candidate" if entry in candidates else "stated"
        rest = {
            key: value
            for key, value in entry.items()
            if key not in ("property", "value")
        }
        print(f"[{kind}] {entry['property']}: {text(entry['value'])}")
        print(f"    {text(rest)}")


def show_manifest(manifest):
    """Print a manifest as canonical YAML, its context reduced to the prefixes."""
    prefixes = {
        key: value
        for key, value in manifest["@context"].items()
        if key not in FORMAT_CONTEXT
    }
    print(dumps({**manifest, "@context": prefixes}), end="")

The bundle holds the three timelines: the encoding clt_6 in quarters, 27 of them for six bars of 9/8; the video cpt_1 in seconds, of unknown length, with a child cpt_2 for the part the example uses; and the WAV file dpt_1 in samples.

bundle = tta.AlignmentBundle(
    id="layerit", name="LayerIt, Clair de lune mm. 1–6 (Pires)"
)
score = tta.ContinuousLogicalTimeline(
    length=27, uid="clt_6", name="Clair de lune, mm. 1–6 (MEI)"
)
video = tta.ContinuousPhysicalTimeline(
    length=None, uid="cpt_1", name="Maria João Pires live at Jardin Musical"
)
video.create_child(length=33.353016, uid="cpt_2")
wav = tta.DiscretePhysicalTimeline(
    length=1470868, uid="dpt_1", name="ClairDeLune_MariaJoaoPires_untilM6.wav"
)
for timeline in (score, video, wav):
    bundle.add_timeline(timeline)
bundle.timeline_ids
['clt_6', 'cpt_1', 'dpt_1']

Say what the bundle and a timeline are

add_statement() states one pair on a timeline or a bundle, in place. The bundle is about the work, named here by its Wikidata item; the value is a node, a thing with an id and a label cached for display. The video’s timeline is a video: type takes a class, and the catalogue’s verb is_a states the same in Wikidata’s vocabulary, as an instance of (wdt:P31) the item for a video, wd:Q98069877. add_verb() takes the verb, the system and the value, and states the pairs the catalogue’s pattern for them gives.

bundle.add_statement("schema:about", {"id": "wd:Q29117946", "label": "Clair de lune"})
video.add_statement("type", "schema:VideoObject")
video.add_verb("is_a", "wikidata", "wd:Q98069877")
video.statements
{'type': ['schema:VideoObject'], 'wdt:P31': [{'id': 'wd:Q98069877'}]}

One verb, two vocabularies

The pianist is named in two systems: by a Wikidata item through Wikidata’s property “performer” (wdt:P175), and by a VIAF identifier through the MARC relator “performer” (rel:prf), the fallback for a system without a property of its own. Each pair holds a node of its own.

video.add_verb("performed_by", "wikidata", "wd:Q235650", label="Maria João Pires")
video.add_verb("performed_by", "fallback", "viaf:113931950")

get_rectangles() gathers the pairs the catalogue reads as one verb about one thing. So far the two performers are two things. A value node is a subject too: node= addresses it by its path, the property and the index, and schema:sameAs on the Wikidata node ties the two. The pairs then form one rectangle, labelled by the node’s label.

video.add_statement("schema:sameAs", {"id": "viaf:113931950"}, node=("wdt:P175", 0))

Who said so, and who believes it

A pair without a provenance entry is stated by the manifest’s publisher. provenance= gives the pair an entry naming who stated it, when, how and why; the keys are those the file writes. actor= records the person stating the pair as believing it, with the belief "true" and the day. A loader or a service records how a pair was made and holds no belief. get_provenance() answers the entries.

video.add_statement(
    "schema:sameAs",
    {"id": "https://www.youtube.com/watch?v=Ch2mrPm1JnM"},
    provenance={
        "stated_by": [EDITOR],
        "date": DAY,
        "method": "manual",
        "note": "pasted URL",
    },
    actor=EDITOR,
    date=DAY,
)
video.get_provenance()
[{'property': 'schema:sameAs',
  'value': {'id': 'https://www.youtube.com/watch?v=Ch2mrPm1JnM'},
  'stated_by': ['https://example.org/people/editor'],
  'date': '2026-11-18',
  'method': 'manual',
  'note': 'pasted URL',
  'beliefs': [{'actor': 'https://example.org/people/editor',
    'belief': 'true',
    'date': '2026-11-18'}]}]

Candidates and beliefs

A candidate is a pair held only as its entry: the subject does not state it, and it waits for someone to. add_candidate() offers one. The WAV file was cut from the video’s sound, which is an inference. A value naming an element of the manifest is the node of its reference, # followed by its ID, which to_file_id() builds.

source = {"id": to_file_id(video.id)}
wav.add_candidate(
    "dcterms:source",
    source,
    stated_by=EDITOR,
    method="inferred",
    date=DAY,
    note="assumed ripped from the video's sound and cut",
)
show(wav)
[candidate] dcterms:source: {"id": "#cpt_1"}
    {"stated_by": ["https://example.org/people/editor"], "date": "2026-11-18", "method": "inferred", "note": "assumed ripped from the video's sound and cut"}

Stating the candidate with add_statement() makes it a pair of the subject; its entry keeps every key and records the person stating it as believing it.

wav.add_statement("dcterms:source", source, actor=EDITOR, date="2026-11-19")
show(wav)
dcterms:source: {"id": "#cpt_1"}
[stated] dcterms:source: {"id": "#cpt_1"}
    {"stated_by": ["https://example.org/people/editor"], "date": "2026-11-18", "method": "inferred", "note": "assumed ripped from the video's sound and cut", "beliefs": [{"actor": "https://example.org/people/editor", "belief": "true", "date": "2026-11-19"}]}

Any actor may record a belief in any pair with add_belief(): "true", "false" or "unlikely", at most one per actor, a later one replacing the earlier. A belief never changes what is stated: a reviewer who believes the source "false" leaves the pair in place, and nothing derives a truth value from the beliefs. The belief filter reads them for one actor, the believer, keeping the states listed in beliefs= ("true", "undecided" where the believer holds no belief, "unlikely", "false"); by default every state but "false".

wav.add_belief(
    "dcterms:source", source, actor=REVIEWER, belief="false", date="2026-11-20"
)
(
    wav.statements,
    len(wav.get_provenance(believer=REVIEWER)),
    len(wav.get_provenance(believer=EDITOR, beliefs=["true"])),
)
({'dcterms:source': [{'id': '#cpt_1'}]}, 0, 1)

A candidate an actor believes "false" was examined and refused; it is kept, so that it is not offered to that actor again. A lookup in the GND offers its entry “Clair de lune” as the work the encoding is an example of; it is Debussy’s song on Verlaine’s poem, not the piano piece. The entry keeps how the candidate was found beside the belief. get_candidates() answers every candidate, and with believer= those the believer does not believe "false".

Describe a region

A region stands for the stretch of its timeline’s manifestation it marks. Regions are frozen: with_statement() returns a copy holding the pair, and replace_region() stores it in the place of the region with its ID. The region’s siblings without_statement(), with_candidate(), with_belief(), with_verb() and with_prefix() mirror the timeline’s remove_statement(), add_candidate(), add_belief(), add_verb() and add_prefix().

opening = score.create_region(0, 9, id="region_1", name="mm. 1–2")
score.replace_region(
    opening.with_statement("rdfs:comment", "the opening, before the melody enters")
)
opening.statements, score.get_region("region_1").statements
({}, {'rdfs:comment': ['the opening, before the melody enters']})

to_dict() writes each element’s statements and provenance where the element stands, and an @context holding the format’s terms and the prefixes the statements use, no others. Import an MEI header

An MEI file’s meiHead describes the work it encodes, the work’s expressions, the manifestations embodying them and the items exemplifying those. MeiHeadLoader states that description in LRMoo’s and MeLODy’s vocabulary. The header below is a short one modelled on the Carl Nielsen Edition’s header of the song Hr. Olufs Sang, CNW 133; the autograph’s address is invented.

HEADER = """<?xml version="1.0" encoding="UTF-8"?>
<mei xmlns="http://www.music-encoding.org/ns/mei" meiversion="5.1">
 <meiHead>
  <fileDesc><titleStmt><title>Hr. Olufs Sang</title></titleStmt><pubStmt/></fileDesc>
  <workList>
   <work xml:id="work_1">
    <identifier xml:id="identifier_1" label="CNW">133</identifier>
    <title xml:id="title_1" type="main" xml:lang="da">Hr. Olufs Sang</title>
    <composer><persName xml:id="persName_1" role="composer">Carl Nielsen</persName></composer>
    <lyricist><persName xml:id="persName_2"
      auth.uri="https://d-nb.info/gnd/" codedval="119018934">Holger Drachmann</persName></lyricist>
    <expressionList>
     <expression xml:id="expression_1">
      <title xml:id="title_3">Version for voice and piano</title>
      <key xml:id="key_1" pname="f" accid="s" mode="minor"/>
     </expression>
    </expressionList>
   </work>
  </workList>
  <manifestationList>
   <manifestation xml:id="source_1">

create_bundle(into=…) states the description on an existing bundle, and subjects= maps the xml:id of a manifestation or an item to one of its timelines or regions. Importing again adds nothing: a pair already stated or held as a candidate is passed over, so a decision stays. base= gives the MEI file’s published address, from which every IRI and basis built from an xml:id then begins.

Import a MeLODy repository

A MeLODy data repository keeps one Turtle file per entity: a work, an expression, a manifestation, an item, a person. Its statements are pairs already, so MelodyLoader carries them as they are, in LRMoo, MeLODy’s own terms and schema.org. The repository below is written for this guide in the shape of MeLODy’s template.

PREFIXES = """\
@prefix melod: <https://lod.academy/melod/vocab/ontology#> .
@prefix melodTerms: <https://lod.academy/melod/vocab/terms#> .
@prefix lrmoo: <http://iflastandards.info/ns/lrm/lrmoo/> .
@prefix owl: <http://www.w3.org/2002/07/owl#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix schema: <https://schema.org/> .
"""
REPOSITORY = {
    "works/1.ttl": """\
<urn:uuid:works/1> a melod:Work ;
  melod:hasTitle [ a melod:Title ; rdfs:label "Clair de lune"@fr ] ;
  owl:sameAs <http://www.wikidata.org/entity/Q29117946> ;
  lrmoo:R3_is_realised_in <urn:uuid:expressions/2> .
""",
    "expressions/2.ttl": """\
<urn:uuid:expressions/2> a melod:Expression ;
  rdfs:label "Clair de lune, piano" ;
  melod:hasContribution [ a melod:Contribution ; melod:hasAgent <urn:uuid:persons/3> ;
    melod:hasRole melodTerms:Composer ] .
""",
    "persons/3.ttl": """\
<urn:uuid:persons/3> a melod:Person ; schema:givenName "Claude" ;
  schema:familyName "Debussy" ; owl:sameAs <http://www.wikidata.org/entity/Q4700> .
""",
    "manifestations/4.ttl": """\
<urn:uuid:manifestations/4> a melod:Manifestation ;
  melod:hasTitle [ a melod:Title ; rdfs:label "Suite bergamasque, first edition" ] ;
  lrmoo:R4_embodies <urn:uuid:expressions/2> .
""",
    "items/5.ttl": """\
<urn:uuid:items/5> a melod:Item ; rdfs:label "Copy 1" ; melod:hasShelfmark "TEST 1" ;
  lrmoo:R7_exemplifies <urn:uuid:manifestations/4> .
""",
}
repository = FOLDER / "melody"
for relative, turtle in REPOSITORY.items():
    path = repository / relative
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(PREFIXES + turtle, encoding="utf-8")

suite = MelodyLoader.from_file(repository).create_bundle(
    id="clair_de_lune", date="2026-11-19"
)
[(tl_id, suite.get_timeline(tl_id).name) for tl_id in suite.timeline_ids]
[('cgt_1', 'Suite bergamasque, first edition')]
