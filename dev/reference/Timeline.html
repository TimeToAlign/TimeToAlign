Timeline

timelines.Timeline(
    length=0,
    unit=None,
    number_type=None,
    uid=None,
    name=None,
    locked=False,
    meta=None,
)

A positive coordinate axis with events and nested child timelines.

A Timeline represents a temporal dimension in one of three domains (Logical, Physical, Graphical) with either continuous or discrete coordinates. It stores events in an EventData and can contain nested child timelines (segments) at specified offsets.

Intended usage: This base class provides the full Timeline API but does not enforce domain or modality constraints. For typical usage, prefer one of the six concrete subclasses or the create_timeline() factory function:

  • ContinuousLogicalTimeline – beats, quarters, measures (Fraction)
  • DiscreteLogicalTimeline – ticks (int)
  • ContinuousPhysicalTimeline – seconds, ms, minutes (float)
  • DiscretePhysicalTimeline – samples, frames (int)
  • ContinuousGraphicalTimeline – cm, inches, points (float)
  • DiscreteGraphicalTimeline – pixels (int)

These subclasses restrict allowed units and number types to prevent accidental cross-domain errors and provide sensible defaults.

Direct instantiation of Timeline is appropriate for internal use, generic algorithms that operate across domains, or advanced scenarios where domain constraints are intentionally relaxed.

If you have a Timeline instance and need the appropriate typed subclass, use :meth:to_typed.

Attributes

Name Type Description
id str Unique identifier for this timeline.
unit TimeUnit The time unit for coordinates (e.g., seconds, quarters, pixels).
number_type NumberType The numeric type for coordinates (int, float, Fraction).
domain Domain The temporal domain (derived from unit).
origin Coordinate The start coordinate (always 0).
length Coordinate | None The end coordinate, or None when the length is unknown.
is_locked bool Whether the timeline’s length is fixed.
is_discrete bool Whether the timeline uses discrete coordinates.
is_continuous bool Whether the timeline uses continuous coordinates.
statements dict[str, list[Any]] What the timeline stands for, as property–value pairs, with their :attr:provenance (see :mod:~timetoalign.timelines.statements).

Examples

>>> # Preferred: use concrete subclasses
>>> from timetoalign.timelines import ContinuousPhysicalTimeline
>>> audio = ContinuousPhysicalTimeline(length=180.0)
>>> # Or use the factory to auto-select the right subclass
>>> from timetoalign.timelines import create_timeline
>>> tl = create_timeline(loader)
>>> # Direct base class (internal/advanced use)
>>> from timetoalign.core import TimeUnit
>>> tl = Timeline(length=100, unit=TimeUnit.seconds)

timelines.Timeline.add_belief(
    property,
    value,
    *,
    actor,
    belief,

Record actor’s belief in the pair (property, value).

The pair’s entry, made where the pair has none, records the belief, replacing the actor’s earlier one (:func:timetoshare.with_belief). Whether the pair is stated is left as it is: believing a stated pair "false" records the belief and never removes the pair, and every other actor’s belief stands. A candidate the actor believes "false" is left out of :meth:get_candidates for that actor.

add_child

timelines.Timeline.add_child(
    child,
    offset,
    allow_expansion=False,
    use_conversion_map=None,
    *,
    locked=None,
)

Embed a child timeline at the specified offset.

The child timeline is locked once added unless locked=False, which leaves its own state as it is. An unlocked child may change its length, but only within this timeline’s known end: this timeline never grows because a child grew. A segment of a segment line is never locked: the line’s lock governs it, and the segment’s own lock is lifted when it joins. A segment line is locked like any child, whether it becomes a child or a segment; unlocking it is not supported yet, so locked=False is refused for a segment line that is unlocked, and accepted (asking for nothing) for one already locked. Parent-child coordinate conversion uses exact offset arithmetic.

The child’s whole subtree joins this timeline’s manifest, in which every id is unique across all element kinds: an element of the subtree whose minted id is already held here receives a freshly minted one, and an element whose given id is already held here makes the call raise without changing anything.

A timeline can accommodate events and other timelines, called Children, as long as they use the same measuring unit.

When the child uses a different unit than the parent, set use_conversion_map to automatically convert the child to the parent’s unit via a C-Map. The parent must have a C-Map whose target_unit matches the child’s unit, so that inverting it yields the child_unit -> parent_unit conversion. The child’s events are copied with converted coordinates; the original child is NOT modified.

The converted child is named "{child.name} [{parent.unit}]" and receives a minted id.

Parameters

Name Type Description Default
child Timeline The timeline to embed. required
offset CoordinateSpec The start coordinate on this timeline, in the parent’s unit. When use_conversion_map is set, the offset must already be expressed in the parent’s unit (e.g. samples). required
allow_expansion bool If True, expand this timeline if needed. False
use_conversion_map ConversionMapsSpec Conversion map specification for unit conversion. Accepts the same formats as the conversion_maps parameter in timestamp functions: - None (default): No conversion; units must match. - True: Auto-select a parent C-Map whose target unit matches the child’s unit. - str: Look up by C-Map ID or target unit name. - TimeUnit: Find by target unit. - ConversionMap: Use directly. None
locked bool | None Whether to lock the child. None (the default) locks every child but a plain segment, which is never locked. False keeps the child’s own state: an unlocked child stays unlocked, a locked one stays locked; it is refused for an unlocked segment line. None

Raises

Name Type Description
TypeError If child is not a Timeline.
ValueError If units don’t match (and no conversion map given), the offset is negative (not supported yet), the child is already a child of this timeline, locked=True asks to lock a plain segment, locked=False asks to leave a segment line unlocked, an id given in the child’s subtree is already held in this manifest, or this timeline is locked and the child would end beyond its length without allow_expansion. An unlocked timeline expands to fit the child instead, provided its own parent contains its new end. A child of unknown length has no end, so only its offset must fit; a parent of unknown length has no end to exceed, unless it is a segment, which ends at its successor’s offset.

add_conversion_map

timelines.Timeline.add_conversion_map(cmap)

Add a ConversionMap to this timeline.

Any map with a target_unit is automatically registered in the unified timestamp system so that :meth:get_timestamp can resolve coordinates in that unit. The map is stored as-is: TableMap instances honor their own kind (nearest/previous/next/linear) and extrapolate policy directly, and analytical maps (e.g. ScalarMap, LinearMap) are likewise stored directly.

Several maps may target the same unit — a piece can carry two readings of the same axis — and nothing is ever displaced: the unit registry holds a list, stamps and tables show every reading, and scalar lookup refuses to guess between them unless the caller names one.

The map’s id must be unique in this timeline’s manifest: a minted id already held there is replaced by a freshly minted one (on the map itself), a given one raises.

Parameters

Name Type Description Default
cmap ConversionMap[Any] The ConversionMap to add. required

Raises

Name Type Description
ValueError If the map’s source unit is incompatible, the map is already attached, or its given id is already held in this timeline’s manifest.

add_events

timelines.Timeline.add_events(rows, allow_expansion=False)

Add events to the timeline.

Only event_type and a coordinate are strictly required per dict. Missing fields are filled in automatically:

  • id: minted above every ID held on this timeline, its prefix the event type in lower case: note_1, beat_1, projection_1. An ID once given on the timeline is never given again.
  • temporal_type: inferred from keys – "interval" when both start and end (or duration) are present, "instant" otherwise.

Positions are stored on this timeline’s axis. A start, end or instant given as a :class:~timetoalign.core.Coordinate in another unit is converted through the timeline’s C-Map; a duration given as a :class:~timetoalign.core.Duration (or Coordinate) in another unit is the span from the start it is added to, converted as the two ends of that span are, so its start must be given in the same unit. Each converted value is written in the timeline’s number type. Bare numbers and struct dicts are taken as on this timeline’s axis.

A Projection (event_type "Projection") holds id, its position and projection_of, the event of another timeline it stands for, as a dict {"timeline_id": ..., "event_id": ...} or an :class:~timetoalign.core.EventReference (None where none is known); it repeats nothing else of that event.

A Box (event_type "Box") is an area of the image the timeline runs along: its shape, in the image’s space, and the interval of its x extent on the timeline. The flow control is played with the three conventions (:func:~timetoalign.timelines.flow.engine.play). get_slice

timelines.Timeline.get_slice(
    start,
    end,
    *,
    truncate_events=True,
    include_children=True,
    copy_cmaps=True,
)

Extract a portion of this timeline as a new, independent timeline.

Returns a new timeline containing all events within [start, end). The returned timeline has its coordinate origin at 0, with all coordinates shifted by -start.

Slicing creates a new timeline that is a structural copy of the specified interval of the source.

A timeline holding Boxes (itself or a descendant) stands for an area of an image (meta["box"]): the slice states the part of that area over its x extent (the area as written where the slice covers the whole timeline), and meta["image"] is carried over, so a Box keeps its shape, in the image’s space, and its start moves with the slice’s origin. meta is otherwise free-form: a timeline holding no Box gives the slice none of it.

Known issues: a Box crossing a slice boundary cannot be clipped (its interval would contradict its shape), so with truncate_events the slice is refused; slice with truncate_events=False to leave such a Box out (the flag holds for the slices of the children too). The area of a proper slice of a quadrilateral area is the slice of its bounding box. A timeline holding Boxes that states no area moves a Box of its own only into a slice starting at 0; its children are sliced by this rule in turn, so a page made of accolades is sliced accolade by accolade, each slice stating its own area.

Parameters

start CoordinateSpec Start coordinate (inclusive). required
end CoordinateSpec End coordinate (exclusive). required
truncate_events bool If True (default), interval events straddling the slice boundaries are clipped to [start, end). If False, events must be fully contained to be included. Children are sliced alike. True
include_children bool If True (default), child timelines whose span overlaps [start, end) are recursively sliced and included. True
copy_cmaps bool If True (default), ConversionMaps are bounded-copied for the slice range. True

to_dict

timelines.Timeline.to_dict(
    minimal=True,
    events=False,
    external_references=False,
)

Write a TimeToShare manifest holding this timeline as its one root.

The timeline object is the timeline’s structure: its axis, children, conversion maps, regions and flow control, and its statements and provenance (see :mod:~timetoalign.timelines.statements). Its measure map is a MeasureRecordMap among the conversion maps (chained after a LinearMap to quarters on an axis in whole notes or ticks) naming an entry of the manifest’s measure_maps, which also holds every measure map a measure view names; equal measure maps share one entry. The metric hierarchy has no manifest form and is not written. Every conversion map is written as one of the format’s map types (see :meth:ConversionMap.to_dict <timetoalign.maps.ConversionMap.to_dict>). The library’s class is not written: the unit decides it. A value on the timeline’s own axis — length, a child’s offset, region start/end, a flow-control element’s coordinate — is written bare, represented as the axis’s number type selects (8, 8.0, [8, 1]); a length of None is written null. "events" and "external_references" are written only on request. The FlowMaps naming the timeline and the virtual timelines that come from its tree are written at the manifest’s top level (flow_maps, virtual_timelines), each list sorted by id and left out when empty.

By default every key at its default value is left out, except length (the minimal form); with minimal=False every optional key is written, its default value included (the complete form). Keys the library does not know, kept when the timeline was read, are written back. A timeline read from a manifest as a whole writes that manifest’s id, name, meta, statements, graphical and unknown keys back around it. :meth:to_file writes the manifest as a file. Every manifest carries its inline JSON-LD @context: the format’s terms and the prefixes its statements use.

The manifest is written whole and valid wherever the timeline belongs: a value naming a timeline or region this manifest leaves out (another timeline of the bundle) is left out with its provenance.

Collections are written in one canonical order, independent of the order in which their content was added, so equal timelines give equal text: children by offset, then id; conversion_maps by id; regions by start, then end, then id; flow_control (every element in one array, see :meth:FlowControlRegistry.to_dict <timetoalign.timelines.flowcontrol.FlowControlRegistry.to_dict>) by coordinate, then id; measure_maps by id. Values compare exactly and ids by Unicode code point. The timeline’s own storage is not reordered, and :meth:from_dict accepts any order.

Parameters

Name Type Description Default
minimal bool If False, write every optional key, its default value included. True
events bool If True, write an "events" key on every timeline object holding its event rows. False
external_references bool If True, write an "external_references" key on every timeline object holding the reference table as a list of row dicts (access_points as a nested list of {"uri": ..., "kind": ...} dicts), even when it is empty. False

Returns

Name Type Description
dict[str, Any] A JSON-serializable manifest {"timetoshare": "0.2.0", ..., | | | [dict](`dict`)\[[str](`str`), [Any](`typing.Any`)\] | "timelines": [timeline]}, every ID written # followed by
dict[str, Any] the ID, as a manifest file writes it.

Raises

Name Type Description
ValueError If a conversion map has no TimeToShare form or cannot be written losslessly, a measure map’s given id is held by another measure map or by a timeline, group or the manifest, two timelines or regions use one prefix for two namespaces, or the statements written break a rule of the format, in TimeToShare’s words (#/timelines/0/statements/dcterms:source/0/id: '#ghost' names no element of this manifest).

Examples

>>> from timetoshare import FORMAT_CONTEXT
>>> from timetoalign.timelines import ContinuousLogicalTimeline
>>> score = ContinuousLogicalTimeline(length=8, uid="piece")
>>> score.to_dict() == {
...     "@context": dict(FORMAT_CONTEXT),
...     "timetoshare": "0.2.0",
...     "timelines": [{"id": "#piece", "unit": "quarters", "length": [8, 1]}],
... }
True

to_file

timelines.Timeline.to_file(
    path,
    *,
    minimal=None,
    styling=None,
    serialization=None,
    events=None,
    external_references=None,
)

Write the object’s manifest to a file.

The manifest is to_dict’s complete form, written with timetoshare.dumps_file in the form, styling and serialization chosen: every object’s keys sorted, its arrays in canonical order, so that equal manifests give equal text and a change shows in a diff as the lines it touches. Each argument left None takes the value the file the object was read from had (see :meth:from_file); for an object not read from a file, the minimal form, the styling included, in canonical YAML, without event rows or external references. An :class:~timetoalign.alignment.AlignmentBundle holding MatchClaims or Projections writes its tables beside the manifest and names them in its resources: its manifest is written (validated and serialized) once before any table, and once more naming the tables written. The manifest validated is the one the file holds: without its styling where styling=False leaves the styling out, so a manifest whose styling the format refuses (a named timestamp beyond the length its timeline was given since) is written without it.
